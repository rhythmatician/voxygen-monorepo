# Server Harness — reproducible dev/test/harvest Minecraft server environment

Owned by `tools/server-harness/`, not by the replaceable Fabric implementation.

## Layout

```
tools/server-harness/
├── README.md
├── mods.manifest.json      # pinned mod versions + sha256 for verification
├── server.manifest.json    # pinned Fabric loader / Minecraft server jar hashes
├── config/                 # tracked harness configuration (copied into runtime on install)
│   ├── chunky/config.json
│   ├── chunky/tasks/minecraft/overworld.properties
│   └── voxyworldgenv2.json
├── scripts/
│   ├── install.sh          # reconstruct runtime/ from manifests (bash)
│   └── install.ps1         # reconstruct runtime/ from manifests (PowerShell)
└── runtime/                # disposable, git-ignored — reconstructed by install script
    ├── fabric-server-mc.1.21.11-loader.0.18.4-launcher.1.1.1.jar
    ├── versions/1.21.11/server-1.21.11.jar
    ├── mods/*.jar
    ├── config/             # copied from ../config
    └── server.properties   # generated by tooling (single source of truth via server_manager)
```

`runtime/` is wholly disposable and ignored. Do not commit jars or generated `server.properties`/`world/`/`logs/` inside it.

## Reconstructing

From a clean checkout (no `runtime/`):

```bash
bash tools/server-harness/scripts/install.sh
# or on Windows
powershell -ExecutionPolicy Bypass -File tools/server-harness/scripts/install.ps1
```

The script:
- creates `runtime/` and `runtime/mods/`, `runtime/versions/1.21.11/`
- fetches the Fabric server launcher and vanilla server jar, verifying sha256
- fetches tracked mods (Voxy, Fabric API, Chunky, Sodium) from Modrinth, verifying sha256
- copies `config/` into `runtime/config/`
- leaves `data-harvester` and `lodiffusion` jars to be built locally (`tools/data-harvester` and `java/`)

Built jars are not tracked here; build them separately:
```bash
./tools/data-harvester/gradlew -p tools/data-harvester build
./java/gradlew -p java build
# then copy to runtime/mods if needed for ad-hoc harvest:
cp tools/data-harvester/build/libs/data-harvester-*.jar tools/server-harness/runtime/mods/
cp java/build/libs/lodiffusion-*.jar tools/server-harness/runtime/mods/
```

## Pinning

Hashes are the reproducibility contract. Edit `mods.manifest.json` / `server.manifest.json` to bump a version, then update the install scripts and `.ci/voxy-artifact.json` (which shares the Voxy hash). CI verifies the pinned Voxy identity via `.ci/install-voxy.sh verify` without relying on a committed jar.
